# chunking Specification

## Purpose

Cuts every page into passages small enough to score and cite, keeping the
heading path and pdf-ingest page and block IDs so a reader can find the
exact place each passage came from.

## Requirements

### Requirement: Split by headings, then by size
Pages SHALL be split at markdown headings into sections. A section longer
than `chunk.size` characters (default 1000) SHALL be split into chunks of
at most `chunk.size` characters, where each chunk after the first repeats
the last `chunk.overlap` characters (default 100) of the previous one.
Splits SHALL fall on a paragraph, line, or word boundary when one exists
in the second half of the window. Sections with no text after stripping
SHALL produce no chunk. Headings inside fenced code blocks SHALL NOT split
a section.

#### Scenario: Two sections
- **WHEN** a page has the headings "A" and "B", each with 200 characters of text
- **THEN** it produces two chunks, one per section

#### Scenario: Long section
- **WHEN** a section has 2500 characters of text with `chunk.size = 1000` and `chunk.overlap = 100`
- **THEN** it produces three chunks of at most 1000 characters each, and each later chunk starts with text from the end of the previous one

#### Scenario: Heading in code
- **WHEN** a fenced code block contains a line starting with `# `
- **THEN** that line does not start a new section

### Requirement: Heading path
Each chunk SHALL carry its heading path: the text of every heading above
it, from the top level down. Text before the first heading SHALL have an
empty heading path. Heading text SHALL NOT be repeated in the chunk text.

#### Scenario: Nested headings
- **WHEN** text sits under "## Results" and then "### Latency"
- **THEN** its chunk has the heading path `["Results", "Latency"]`

### Requirement: Chunk identity and order
Each chunk SHALL carry its source ID, its position (0, 1, 2, … in page
order), and a `chunk_id` from core-contracts. Positions SHALL be assigned
before duplicates are removed, so IDs do not depend on other pages.

#### Scenario: Same page, same IDs
- **WHEN** one page is chunked alone and again together with other pages
- **THEN** its chunks have the same IDs both times

### Requirement: Stripped content
Chunk text SHALL NOT contain HTML comments, images (markdown images and
`<img>` tags, including `data:` payloads), or link URLs. A markdown link
SHALL keep its text and lose its URL; an image SHALL keep its alt text;
an autolink SHALL be removed.

#### Scenario: Link and image
- **WHEN** a section contains `see [the docs](https://x.example/d) ![chart](data:image/png;base64,AAAA)`
- **THEN** the chunk text is `see the docs chart`

#### Scenario: Comment removed
- **WHEN** a section contains `<!-- generated by tool -->`
- **THEN** the chunk text does not contain it

### Requirement: pdf-ingest anchors
For pdf-ingest markdown, each chunk SHALL carry the page ID in effect at
its start (from the last `<!-- page: … -->` comment before or at its start)
and the block IDs of every `<!-- a: … -->` comment inside it. Anchor
comments SHALL be removed from the chunk text like other comments.

#### Scenario: Page and blocks
- **WHEN** a pdf-ingest page has `<!-- page: 4 -->` followed by `<!-- a: p4-b1 -->` and text
- **THEN** the chunk of that text has page ID `4` and block IDs `["p4-b1"]`, and its text has no comment

### Requirement: Near-duplicate removal
Chunks whose normalised text is equal SHALL be kept once: the first in input
page order. Normalised text SHALL be lowercased, Unicode NFKC normalised,
with every run of non-alphanumeric characters replaced by one space and the
ends trimmed. The result SHALL report how many chunks were removed.

#### Scenario: Same paragraph on two pages
- **WHEN** two pages contain the same paragraph with different spacing and punctuation
- **THEN** only the chunk from the first page is kept and the duplicate count is 1
